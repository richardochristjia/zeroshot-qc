Prototype: .lavish/ui-redesign/proto/index.html (throwaway; P1–P4 settled there). Decided by me: the top bar gets a System / Light / Dark theme switch, saved in localStorage. Reason: the taste inspector has no colour-scheme flag. Without the switch it can only test the OS theme. QC stations also often need a forced theme.

Problem

  • All 4 pages FAIL the taste inspector today. index.css turns the body dark, but pages hardcode light greys, e.g. bg-white inputs at Inspect.tsx:169. Dark-OS users get unreadable titles and white boxes.
  • No design system: about 60 duplicated class strings, raw Tailwind greys, no tokens, a system font.
  • Each page has two h1s (App.tsx:17 plus each page's own). Eval numbers are left-aligned without tabular figures. Inspect and Synthetic open on a mostly empty screen.
  • Inspect, the main job, reads as a form, not a workbench. The verdict sits below the fold, and detections link to the overlay only on hover.

Solution

Build a small token-driven design system with ui-ux-pro-max: Swiss minimal, Fira type, and colour only on data. Rebuild the shell and all 4 pages on it, following taste-skill's app-screens.md rules: flat surfaces, a receding nav, type-led KPIs, honest empty and zero states, and the product's own name and mark. Then run taste-skill's inspector in a look-and-fix loop until the gate passes.

Product face (taste-skill "one face" rule): a monogram mark drawn from a lens/reticle, in the accent colour.
Signature element: the Inspect compare view. The reference sits beside the part under test, whose numbered boxes match the numbered ruling rows. Hover or focus on either side highlights both.
Semantic colour only: PASS green, FAIL red, detection amber, plus one data hue for metric bars. Everything else is neutral.
Trade words: "Verdict", "Rulings", "Missed defects", "Reference image", "Defect prompts". No generic "Items" or "Records".

Phases

  1. Design system. Run ui-ux-pro-max --design-system, then --stack react/tailwind and the ux-domain checks. Write three token layers (primitive → semantic → component) as CSS variables in index.css, mapped through @theme: colour, type scale, spacing, radius, motion. Define light, dark, and [data-theme] overrides. Add @fontsource/fira-sans and @fontsource/fira-code. Add a short docs/design-system.md listing the tokens and the do/don't rules.
  2. Primitives. In src/components/: Button (primary/secondary/ghost, centred icon + label), Field (label + input/select/textarea + hint/error), Panel, Alert, VerdictBadge, PageHeader, EmptyState, and an Icon sprite with the prototype's icon set. Each gets visible focus rings and 44px touch targets. Add motion and wrap the app in <MotionConfig reducedMotion="user">.
  3. Shell. Rebuild App.tsx as a top bar with mark, name, tabs (neutral active state), a health dot (new getHealth() in api.ts calling the existing /api/health), and the theme switch. Only one h1 per page, owned by the page.
  4. Inspect (prototype C). Profile picker, drop zone (drag-and-drop or file picker; still file-based) and Inspect button on top. Below: Reference card (the profile's reference_image; "No reference set" empty frame when missing) and Under test card with numbered boxes, then the verdict card: FAIL/PASS headline with icon, summary, numbered rulings, timings, rules override. An empty state shows a drop target plus the profile's rules and prompts. All current behaviour is kept: the debounced judge-only re-run, abort on new keystroke, and clear-to-restore.
  5. Profiles. Profile list beside the editor, with the SOP import as its own panel. All current save, overwrite and validation flows are kept.
  6. Eval. Run picker, then a run summary as type-led KPIs (F1, precision, recall, AUROC), then the category table: right-aligned, tabular figures, no zebra. F1 bars use the one data hue. Still read-only.
  7. Synthetic. Image/mask pair grid grouped by profile and defect, plus the existing generate controls.
  8. Motion pass. Use motion only where it carries meaning, at 150–250ms:
    • The verdict card and rulings fade and rise in on a new result, with rulings staggered.
    • Detection boxes draw in after the image loads.
    • A crossfade marks a re-judge with edited rules.
    • Page content fades between tabs.
    • The active tab underline slides (layoutId).
    • The Synthetic grid reflows on filter change (layout).
    • Alerts and the SOP draft preview enter and leave (AnimatePresence).
    • The mask overlay fades.
    Under prefers-reduced-motion nothing moves.
  9. Taste gate loop. Run vite build + vite preview against the backend with USE_FAKE_ADAPTERS=true. Run inspect.mjs --app on 4 routes × light/dark. Read the screenshots, fix the top 3 problems, and repeat, up to 3 rounds. Write the final reports to .plans/ui-redesign/taste/.
  10. Update the Record with the entries below, checked against the final code.

Anti-goals

  • No backend/API change except reading the existing /api/health. No webcam capture, no launching eval runs (both contradict the RECORD).
  • No UI kit and no icon font: icons are inline SVG. motion is the only new runtime dependency besides the fonts. No decorative or looping animation, and no motion on numbers that update.
  • No KPI tiles with tinted icon circles or sparklines, no gradients, no emoji (taste-skill tells).

Acceptance criteria

Automated

  1. npm run build, npm run lint, npm test pass in frontend/.
  2. The taste inspector --app reports 0 FAIL on /, /profiles, /eval, /synthetic at 1440/768/390, in both light and dark. Each remaining WARN is listed with its reason and --allow name.
  3. Pages render only colours from tokens: a grep finds no raw neutral-*/red-*/green-*/amber-* Tailwind palette classes in src/pages or src/App.tsx.
  4. Each page has exactly 1 h1.
  5. Browser walkthrough against the fake backend: inspect an image, then edit rules and see the verdict re-judge; save a profile; open an eval run; view the synthetic gallery. Each works at 390px with no horizontal scroll.
  6. The theme switch persists across reload and overrides the OS setting. "System" follows the OS.
  7. With the OS set to reduce motion, no element animates: MotionConfig reducedMotion="user" is in place and the inspector's motion check passes.
  8. Fonts load from the bundle: the built dist/ has .woff2 files and makes no request to fonts.googleapis.com.

Manual

  • manual: With real SAM/Muse keys, run one real inspection. Check that the overlay boxes line up with the defects on a real MVTec image.
  • manual: Open the docker-compose build (docker compose up) and check that the fonts and theme render behind nginx.

What the probes showed

  • Taste inspector on the current app (dev server, fake backend, OS dark): 4/4 FAIL, all on contrast. WARNs: many-h1, hero-void, unused-canvas, numeric-align, tabular. This confirmed the dark-mode break is real, not theoretical.
  • The inspector has no colour-scheme flag. It follows the OS. That shaped the design: the theme switch makes light/dark testable.
  • The inspector drives the local Chrome over CDP and needs no npm install. It works against localhost.
  • The backend runs with USE_FAKE_ADAPTERS=true, no keys needed. The /api/profiles data and existing data/runs + data/synth give every page real content for the gate.
  • Throwaway prototype with real profiles, eval metrics and the fake inspect shape. Inspect C: 0 FAIL at 1440/768/390. Its one WARN (the image cards end shorter than the verdict card) becomes a named --allow. It also caught that inline grid styles beat media queries (tablet overflow), and that the icons widen the top bar at 768px, so the theme switch shows icons only there.
  • motion@14.7.1 peers allow React 18 and 19, so it is compatible with this app's react@^19.3.
  • Data issue (out of scope): data/synth/bottle/scratch/*.png show cats, dogs and a portrait, not bottles. The Synthetic page renders whatever is there. Generation needs its own diagnosis.
  • ui-ux-pro-max --design-system suggested a Swiss minimal style with Fira Sans/Code (kept). It also suggested a navy/green palette (adapted: colour only on data) and a "Hero + CTA" landing pattern (dropped, wrong for an app).
