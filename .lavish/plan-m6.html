Problem

Everything works, but only from a terminal: inspecting a part means a CLI command, rules are edited as flags, profiles as JSON, and eval numbers as printed tables. The hackathon judges must see the headline moment in a browser — upload a photo, get PASS/FAIL with outlined defects and written reasons, edit a rule in plain English, watch the verdict flip instantly with no retraining. No page exists yet, and no router serves anything the pages will need.

Solution

Scaffold frontend/ with Vite + React + TypeScript + Tailwind (HANDOFF stack) and implement the four pages against real backend routers built to HANDOFF §8. The live rule editor needs no server sessions: it re-sends the image with edited rules, and the existing disk cache serves segmentation while only the judge re-runs — debounced. Images (uploads, overlays, synth, eval examples) are served from data/ under /files/.... Dev runs as Vite (proxy) + uvicorn; deploy stays M7.

Phases

  1. Backend routers. Implement the four stub routers to §8: POST /api/inspect (multipart image + profile_id + optional rules → InspectionResult, 422 on double judge failure), profiles GET/PUT + existing from-sop, synth generation endpoint, eval run list/detail, /files/... static serving from data/ (gitignored content stays uncommitted).
  2. Frontend scaffold. frontend/ (Vite + React + TS + Tailwind), typed API client, router with 4 pages, dev proxy to the backend.
  3. Inspect page. Profile picker, file upload, overlay with hoverable detections, verdict card with per-ruling reasons, rules textarea that re-runs the judge debounced (segmentation served from cache).
  4. Profiles page. List, edit (PUT), “Import from SOP” via the M5 draft endpoint with save-as-new confirmation.
  5. Eval + Synthetic pages. Eval: run list, per-category metrics table, ablation bar chart, clickable failure examples — read-only. Synthetic: gallery grouped by category and defect type from data/synth/.
  6. Record. Append the M6 entries (below) after verifying them against the build.

Acceptance Criteria

  • End-to-end inspect works in the browser: upload → overlay with hoverable detections → verdict card with reasons.
  • Editing rules in the textarea flips the verdict without re-uploading (judge-only rerun, visibly fast).
  • Profiles list/edit/SOP-import round-trips; Eval shows table + chart + clickable failures; Synthetic gallery groups correctly.
  • pytest green (router tests via TestClient); frontend tsc + build clean; no secrets in frontend code.
  • manual: full walkthrough on a second device against the dev servers (upload, rule flip, SOP import, gallery).
