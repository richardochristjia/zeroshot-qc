Problem

Small factories inspect by eye because automated inspection needs thousands of labeled photos per product. ZeroShot QC claims zero-training inspection: SAM 3.1 segments candidate defects from text prompts, Muse Spark judges them against plain-English rules and a known-good reference, Muse Image generates synthetic test data. The whole claim rests on one unproven assumption — that SAM 3.1 text prompts can find small industrial defects (ROADMAP Day-1 risk check). M1 exists to prove the plumbing and surface that risk as early as possible.

Solution

Scaffold the exact HANDOFF §4 layout (backend only in M1; frontend arrives at M6), implement the §6 schemas verbatim, and build the three adapter protocols (§5) with two implementations each: a real Meta HTTP adapter whose request shape is isolated in one module so it can be corrected the moment official docs arrive, and a deterministic fake for tests. A disk cache keyed by sha256 of inputs (§2) wraps every model call from day one, so eval reruns never re-pay. /api/health reports configured model IDs without leaking keys. scripts/smoke.py runs the adapters over 3 MVTec images and reports per-category mask counts — the Day-1 risk signal.

Phases

  1. Scaffold. Repo layout per HANDOFF §4 (backend subtree), .env.example (§11), .gitignore for data/ and keys, pinned deps (FastAPI, Pydantic v2, Pillow, numpy, opencv-headless, pycocotools), README stub noting MVTec CC BY-NC-SA 4.0.
  2. Schemas + config. §6 Pydantic models verbatim in schemas.py; config.py via pydantic-settings reading .env — model IDs never hardcoded (§2).
  3. Adapters. Segmenter / Judge / ImageGenerator protocols (§5); real HTTP adapters with the Meta request/response mapping isolated in one place per adapter; deterministic fakes in fakes.py.
  4. Cache. pipeline/cache.py: disk cache keyed by sha256(image bytes + prompts + model id); a hit must not call the adapter.
  5. Health + smoke. GET /api/health (status + configured model IDs, no secrets); scripts/smoke.py runs SAM over 3 MVTec images × 3 prompts, saves overlays, prints counts; calls the judge once and validates JSON against Verdict.
  6. Data step. Documented MVTec download into data/mvtec/ (manual, license-gated); smoke degrades to a clear “data missing” message, never a stack trace, when absent.
  7. Record. Bootstrap .agents/RECORD.md (see Record Updates) as the last task, verified against what was actually built.

Acceptance criteria

  • GET /api/health returns 200 with status and the model IDs from .env (empty strings when unset — never a key).
  • python scripts/smoke.py with fakes enabled completes on any 3 images, saves overlays, and prints per-prompt mask counts.
  • Judge fake returns output that validates against Verdict on the first attempt.
  • Second identical smoke run is served from cache (adapter call count does not increase).
  • pytest is green; no model ID, endpoint, or key appears anywhere in source.
  • manual: with real keys + official docs pasted in, smoke prints real SAM mask counts for 3 MVTec images — the Day-1 risk readout (works / weak / fallback to golden-sample route per ROADMAP).
