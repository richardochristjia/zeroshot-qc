## Must-fix

### S1. Adapter wiring lives only in the smoke script; the app has no swap point

- **Proof.** The sole fake/real selection point is `build_adapters` at [smoke.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/scripts/smoke.py:46): it constructs `DiskCache(Path(settings.data_dir) / "cache")` (48), wraps fakes with `fake-sam`/`fake-judge` (50-51) or reals with settings IDs (53-58), and is called only from `main()` at [smoke.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/scripts/smoke.py:171). The FastAPI entry point [main.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/main.py:8) imports only `settings` (6), builds CORS (10-17), and registers `GET /api/health` (20-29); it never imports an adapter, the cache, or a router. `grep -rn "build_adapters|DiskCache" backend/app backend/scripts` returns hits only in smoke and `pipeline/cache.py`.
- **Spec.** `plan.md:105` requires the swap point in "`main.py` or a small `deps` module, never scattered `if fake` branches"; `context-pack.md:69` restates selection happens once in `build_adapters` (`smoke.py:46`).
- **Cost.** M2's `routers/inspect.py` cannot reuse the wiring without importing from `backend/scripts/` (a CLI entry point that runs `sys.path` surgery at [smoke.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/scripts/smoke.py:18) and parses argv in `main`) or copy-pasting the cache-root + model-ID + fake-ID block. The second copy will drift (cache root, fake IDs, or model IDs fixed in one place only), and the divergence surfaces as cache misses or fake entries served to real adapters.
- **Fix shape.** Move `build_adapters` (parameterised by `settings` + cache root) to `app/deps.py` or `app/pipeline/wiring.py`; smoke and `main.py`/routers both call it. No behaviour change.

### S2. Cache key model ID and adapter model ID are two reads of the same setting

- **Proof.** Wiring snapshots the ID once: `CachedSegmenter(SamSegmenter(), settings.sam_model_id, cache)` at [smoke.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/scripts/smoke.py:53) and `CachedJudge(MuseSparkJudge(), settings.judge_model_id, cache)` at [smoke.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/scripts/smoke.py:56). The wrappers key on that snapshot: `segment_cache_key(image, prompts, self._model_id)` at [cache.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/pipeline/cache.py:163) and `judge_cache_key(..., self._model_id)` at [cache.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/pipeline/cache.py:198). Each real adapter then re-reads the live global independently: `settings.sam_model_id` in the payload at [sam.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/adapters/sam.py:47), `settings.judge_model_id` at [muse_spark.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/adapters/muse_spark.py:71), guarded against `settings` at [sam.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/adapters/sam.py:26) / [muse_spark.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/adapters/muse_spark.py:33). Adapters import the singleton directly (`from app.config import settings` at [sam.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/adapters/sam.py:18), [muse_spark.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/adapters/muse_spark.py:18), [muse_image.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/adapters/muse_image.py:18)); only the guard/model fields are read at call time.
- **Spec.** `context-pack.md:68` names one shared `settings` instance (`config.py:40`) as the only config contract, and `cache.py:6-8` documents callers pass the model ID in explicitly so the cache never reads settings.
- **Cost.** The key's model component and the request's model component can disagree whenever `settings` is mutated between wiring and call (tests already monkeypatch the singleton; a future `.env` reload or multi-tenant wiring would too). The cache then files a response under model A's key that model B produced — a silent wrong-model hit that the prompt/model-miss tests cannot catch because they construct a fresh wrapper per ID. It also defeats §5 isolation: no real adapter can be instantiated against a non-global config, so unit tests must patch module state instead of constructing the object.
- **Fix shape.** Inject `model_id` (and key/base URL) into each real adapter's constructor from the same wiring function that passes it to the `Cached*` wrapper, so one value feeds both the guard, the payload, and the cache key.

### S3. RLE decode + overlay rendering is stranded in the smoke script

- **Proof.** `_decode_mask` (COCO RLE → binary array) at [smoke.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/scripts/smoke.py:125) and `_make_overlay` (tint blend over decoded masks) at [smoke.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/scripts/smoke.py:142) are the only implementations of mask decoding and overlay drawing in the tree: `grep -rn "mask_api.decode|_make_overlay" backend/app backend/scripts` hits only smoke. HANDOFF §4 assigns this to `pipeline/overlay.py` (see `check-1.md:5`); `plan.md:85` defers overlay labelling to M2 and `context-pack.md:73` records the tint as "smoke-local (`smoke.py:142`), M2 owns `overlay.py`".
- **Cost.** M2 must build `pipeline/overlay.py` while a working copy already exists inside a 267-line CLI script. The two will either diverge (smoke keeps the naive tint, the pipeline gains labels/IDs) or M2 pays an extraction refactor under time pressure, and anyone debugging a wrong overlay today finds the logic in `scripts/` rather than `pipeline/`. The decode helper also swallows every failure (`except Exception: continue` at [smoke.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/scripts/smoke.py:150)), so a real-adapter RLE format change (flagged `TODO(meta-docs)` in the pack, `context-pack.md:72`) would silently render empty overlays instead of surfacing in one shared place.
- **Fix shape.** Extract `_decode_mask`/`_make_overlay` to `app/pipeline/overlay.py` now (smoke imports it); M2 then extends that module instead of forking it.

- **Proof.** PNG→base64 encode exists three times: inline at [sam.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/adapters/sam.py:42), as nested `_encode` at [muse_spark.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/adapters/muse_spark.py:61) and [muse_image.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/adapters/muse_image.py:46) (a fourth copy, `_png_bytes`, lives at [cache.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/pipeline/cache.py:38)). The auth header + POST is verbatim at [sam.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/adapters/sam.py:51), [muse_spark.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/adapters/muse_spark.py:79), and [muse_image.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/adapters/muse_image.py:61) (`httpx.post(url, json=payload, headers=headers, timeout=60.0)`), and the not-configured guard at [sam.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/adapters/sam.py:26), [muse_spark.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/adapters/muse_spark.py:33), [muse_image.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/adapters/muse_image.py:27). Only the payload/response mapping inside `_segment_via_meta_api` (33), `_judge_via_meta_api` (44), `_add_defect_via_meta_api` (34) is per-adapter.
- **Cost.** The `TODO(meta-docs)` isolation (`context-pack.md:43`) correctly confines payload shape to one function per adapter, but a docs correction to auth scheme, timeout, retry, or image encoding must still be applied in three files plus the cache's `_png_bytes`; miss one and adapters behave inconsistently. Cheap to fix now with a tiny `adapters/_http.py` (`encode_png_b64`, `post_json`, `require_configured`) that the private mapping functions call — payloads stay per-adapter.

### S5. `pipeline/` holds only the cache; the package name promises the M2 pipeline

- **Proof.** `backend/app/pipeline/` contains `__init__.py` and `cache.py` only (212 lines); there is no `inspect.py`, `measure.py`, or `overlay.py`. The cache itself is storage infrastructure: `DiskCache` (101), key builders (55, 72), and two decorator wrappers (146, 175) with no inspection logic. Smoke reaches into it directly from the CLI at [smoke.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/scripts/smoke.py:32).
- **Cost.** Minor today, real at M2: the inspection pipeline will land next to a cache that every caller already imports as `app.pipeline.cache`, so "pipeline" becomes a grab-bag (orchestration + storage + wrappers). Naming the storage `app/pipeline/cache.py` also hides that `DiskCache` is generic (any JSON payload) and reusable by eval/synth. Acceptable if M2 adds `inspect.py` alongside and the boundary is documented; alternatively move `DiskCache` to `app/cache.py` and keep `pipeline/` for orchestration only.

### S6. Hash-seeded box geometry copy-pasted in the fakes

- **Proof.** `FakeSegmenter.segment` computes `box_w`/`box_h`/`x0`/`y0` from digest bytes at [fakes.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/adapters/fakes.py:38); `FakeImageGenerator.add_defect` repeats the identical four lines at [fakes.py](/Users/167560.KEVIN/orca/projects/Zeroshot QC/backend/app/adapters/fakes.py:103). The two also seed differently for no structural reason: `_seed_digest(image, prompts)` (20) vs inline `sha256(tobytes + b"\x00" + description)` (99).
- **Cost.** A clamp or seeding fix lands in one fake and not the other; tests assert determinism per fake, so divergence is invisible. One `_seeded_box(digest, width, height)` helper removes the pair.

### S7. Smoke script is five modules in one file (267 lines)

- **Proof.** `smoke.py` bundles: `sys.path` bootstrap (18-20), adapter wiring (46), image discovery with a double recursive scan plus upper-case fallback and linear `path not in found` dedup (62-84, two `rglob` passes at 66 and 73), placeholder synthesis (112), RLE decode (125), overlay rendering (142), `Detection` placeholder mapping (232-243), profile construction (244), and CLI/`main` (161-267).
- **Cost.** Each concern is untestable in isolation (no test imports `_collect_images`, `_decode_mask`, or `_make_overlay`; the only checks are end-to-end smoke runs), and M2 work (measure, overlay, inspect wiring) has no seam to attach to — it must edit the CLI file. Splitting discovery and overlay out (S3 covers overlay) leaves `main` as a thin orchestrator.

### N5. Boundaries that are correct and should not be "fixed"
