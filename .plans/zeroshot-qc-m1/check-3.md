- Plan's Key Code Context snippet is not HANDOFF §5 verbatim: it drops the judge's argument types, the PIL/schemas imports, and gives the image generator a defaulted mask argument, while HANDOFF §5 requires the mask argument typed as an optional image with no default (plan.md:60-70 vs HANDOFF.md:75-103), and tasks.md:21 only says "(§5)" without naming which text wins. Expanded the base-protocol task to pin HANDOFF §5 verbatim as the source so later phases do not each improvise signatures.
- Phase 3 scope for the SOP parser and the image generator is contradictory: Relevant Files limits the judge adapter to judging in M1 with SOP parsing landing in M5 and calls the image adapter "exercised M5" beyond protocol stubs (plan.md:47-48,87), but tasks.md:22 says "Implement real HTTP adapters" for all three files with no stub boundary, leaving SOP-to-profile and defect-generation behaviour in M1 undefined. Split the real-adapter task per adapter: the judge mapping is implemented now with its SOP method left as an explicit not-implemented M5 stub, and the image mapping is present behind the same guard but unexercised until M5.
- The "clear not-configured error" has no contract: the plan requires failing before any network attempt to an empty URL and a test that asserts it (plan.md:94,117), yet names no exception type or message and never says which empty settings fields gate which adapter, even though all key/base/model fields default to empty (backend/app/config.py:22-26). Added tasks pinning one shared not-configured exception in the protocols module, a per-adapter check of its own key/base/model fields, and settings read from the shared instance at call time so the no-network test can empty the fields deterministically.
- The anti-guessing isolation is missing from the task list: the plan requires the whole Meta request/response mapping inside a single private function per adapter with uncertainty marked TODO(meta-docs) and forbids invented endpoints, shapes, or model IDs (plan.md:78,90; HANDOFF.md:16), and httpx is available for it (backend/requirements.txt:6), but tasks.md:22 lumps all three adapters into one line mentioning neither isolation nor TODO markers, so hardcoded guessed paths/auth/payload/image-encoding would satisfy the task as written. Split tasks now require, per adapter, that endpoint, payload, auth, image encoding, and response parsing live inside that one private mapping function, built only from the shared settings values.
- Fake segmentation determinism is unspecified beyond "seeded by input hash" and "fixed small set" (plan.md:79) with per-prompt smoke counts built on it (plan.md:80): tasks.md:23 names neither the seed inputs, the masks-per-prompt cardinality, the label/score rule, nor the mask geometry relative to the actual image size, so a fixed box could claim dimensions the input image does not have. Expanded the fakes task to pin hash seeding over image bytes plus prompts, one mask per prompt labelled by that prompt, deterministic scores, and mask geometry clamped to the real image dimensions with the RLE size matching them.
- The RLE representation the fakes must emit is unsettled: the schema types it as an untyped dict (backend/app/schemas.py:11) and the plan only says "a shape pycocotools accepts" (plan.md:98), while the installed encoder returns a dict whose counts value is bytes (probed read-only), which plain JSON cannot carry and which the later disk cache must serialize. Pinned in the fakes task that emitted counts are stored in the JSON-safe text form of the COCO compressed RLE so cache/API serialization cannot break on them.
- Fake judge validity needs the Phase 2 trap spelled out: acceptance requires first-try validation (plan.md:27) but the ruling's rule field is required-but-nullable (backend/app/schemas.py:39, omitting it fails validation as probed) and confidence is bounded to [0,1] (backend/app/schemas.py:45), and neither the plan nor tasks.md:23 says how fake rulings correspond to the detections passed in. Expanded the fakes task to require one ruling per input detection with the rule field always present, an in-bounds deterministic confidence, and a deterministic verdict/summary, plus a deterministic same-size result from the fake image generator.
- No task creates the tests the phase is judged by: Test Strategies assigns determinism, first-try verdict validation, and the no-network guard to a test file (plan.md:117) and acceptance repeats two of them (plan.md:27,29), but the Adapters tasks (tasks.md:21-23) contain no test-writing line and the tests directory is still empty. Added an Adapters task to create that test file covering determinism, RLE acceptance, verdict validation, and the guarded real adapters.
- The RLE acceptance check itself cannot use decoding on this host: with the pinned numpy/pycocotools pair (backend/requirements.txt:8,10) the installed encoder and uncompressed-RLE conversion succeed but decode/area calls raise a numpy-conversion TypeError (probed read-only), consistent with the split global install already logged (risks.md:5), so "pycocotools accepts" via a decode round-trip would fail for environment reasons rather than fake correctness. Kept the Phase 3 acceptance to encoder acceptance plus structural checks, and logged the decode-path verification in risks.md for a clean environment.
