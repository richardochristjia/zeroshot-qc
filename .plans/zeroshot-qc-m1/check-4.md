Expanded tasks.md to pin length-prefixed components in fixed order (call kind, PNG image bytes, each prompt in list order, model id) with an analogous judge key (images, detections JSON, profile JSON, judge model id) so rule/profile edits miss.
- HANDOFF §7 omits the model id from the cache hash (HANDOFF.md:172) while the plan requires it and tests prompt-change misses (plan.md:18,96); taken verbatim, §7 would serve stale masks after a model swap. Followed the approved plan over §7 (stricter, no behaviour change) and added a model-id-change miss to the cache test task, which Test Strategies omits (plan.md:118 lists only the prompt change).
- Cache API shape is unspecified: the plan says callers build inputs and pass through `pipeline/cache.py` (plan.md:77,106) but names no function, class, or signature, and the stub is a lone docstring (backend/app/pipeline/cache.py:1), so Health + smoke would have nothing stable to import. Pinned in tasks.md a `DiskCache` store plus protocol-shaped `CachedSegmenter`/`CachedJudge` wrappers taking the inner adapter, an explicit model id (from settings at wiring), and the cache store, keeping call sites protocol-identical.

- Cache directory location is unpinned: the plan says `data/cache/` (plan.md:77; HANDOFF.md:69) but config already resolves `DATA_DIR` to an absolute repo-root path (backend/app/config.py:27,32-37), so a hardcoded relative path would drift with the launch directory and ignore the env override. Pinned the store root to `Path(settings.data_dir) / "cache"` (created on demand, already gitignored via .gitignore:2) in tasks.md.
